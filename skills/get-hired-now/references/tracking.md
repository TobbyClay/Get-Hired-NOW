# Tracking, reconciliation and follow-up

Persist actual progress after each material event. Report sightings, qualified
roles, prepared packets, attempted applications and confirmed receipts separately.
A failed validation or security block is not a hiring rejection. Historical
submission totals are not active-candidacy totals.

Reconcile using exact employer/title/requisition and observed evidence. Preserve
accepted receipts and exact submitted files even if a later event is a rejection,
newer draft or failed retry. Deduplicate repeated acceptance screens. Keep unknown
counts unknown rather than reconstructing them from conversation memory.

The private state is canonical. Update an external tracker only if that action
and exact destination are authorized. Map columns/statuses to the destination's
current schema instead of hard-coding a personal sheet or account ID. Record the
actual update result; a proposed row is not a successful remote write.

For requested inbox/recruiter work, use only authorized accounts and the evidence
relevant to the exact job. Draft concise, truthful replies in the person's supplied
voice. Keep application receipt, interview invitation, rejection and uncertainty
distinct. Do not infer employer interest or invent a prior conversation.

Sending a reply/outreach message needs its own authorization or explicit coverage
as part of the application route. Review recipient and current content. Do not
commit the person to availability, terms or compensation they did not supply.
For recurring searches/monitors, use the host's actual scheduler only on explicit
request and preserve notification preferences. No skill invocation automatically
creates/resumes schedules or duplicates an existing monitor.
