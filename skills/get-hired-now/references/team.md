# Roles, ownership and handoffs

These responsibilities can run in one AI or in a host's real subagents. They are
not a required vendor, model roster or separate service. Preserve the user's chosen
models and host restrictions. Do not claim workers are running merely because
these role descriptions exist.

| Role | Concrete responsibility |
| --- | --- |
| Lead | Scope batch, route work, integrate results; own shared state and submissions by default |
| Market scout | Search live broad-market sources; verify actual hiring geography |
| Startup scout | Discover relevant startup roles using candidate-supported problems/skills |
| ATS collector | Extract literal official postings, exact IDs, dates and pagination evidence |
| Fit reviewer | Map mandatory/preferred requirements to actual candidate evidence |
| Salary researcher | Separate employer budget, market evidence and candidate expectations |
| Writer | Produce truthful actual CV/cover-letter files in an assigned private directory |
| Form preparer | Read-only exact-form inspection and grounded answer map |
| Skeptic | Investigate material contradictions/identity/duplicates; no redundant routine review |
| Records clerk | Compare exact receipts/attempts and propose evidence-backed ledger updates |

Use independent, non-overlapping discovery/research/writing slices only when parallel
agents are available and appropriate. One small task can stay with Main. Do not
spawn a second lead simply to plan Main's work. Workers do not spawn more workers.

Every assignment includes batch/source/employer boundary, exact job IDs, relevant
private fact/evidence paths, expected output, owned artifact directory if needed,
submission owner and shared-record owner. Workers return evidence and uncertainty;
they do not receive unnecessary sensitive facts or arbitrary account access.

Supporting roles must not enter candidate data, upload, submit, send messages,
change policy or mutate shared trackers/state. Only an explicitly assigned owner
has that scope, subject to current permissions. Transferring submission ownership
does not transfer shared-record ownership. Stream finished work to the owner while
other independent roles continue. Keep actual worker/tool status visible and honest.
